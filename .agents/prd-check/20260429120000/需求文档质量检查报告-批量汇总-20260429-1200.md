> ⚠️ **文档类型说明**：此文档为 `requirement-complexity-splitter` 工具输出的「需求分析」文档，非传统 PRD。其结构服务于复杂度评估与拆分决策，天然缺少 PRD 模板中的部分章节。

### 评审上下文

| 维度 | 理解 |
|------|------|
| 业务意图 | 让组织管理员在现有 Usage Analytics 看板中直接看到团队 Credit 余额，无需跳转到 Payment Details 页面，快速判断是否需要充值。 |
| 目标用户 | 组织管理员（owner / billing_manager 角色），仅 1 类角色。 |
| 核心流程 | 管理员进入 usage-details 页面 → SummarySection 中新增 Credit 余额卡片 → 看到当前余额（时点值）。仅 `canViewAllOrgUsers` 为 true 时可见。 |
| 成功指标 | 推断性描述，未量化（「管理员能直接看到 Credit 余额」）。 |
| 技术约束 | Credit 余额在 Postgres，现有 Usage Analytics 数据管道全量依赖 Snowflake，需独立查询路径。 |
| 最大风险 | 双数据源语义一致性：Cost 卡片（Snowflake 时间段聚合）与 Credit 余额卡片（Postgres 时点值）口径不同。 |
